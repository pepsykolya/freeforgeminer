- **`cmfd1…` addresses.** The Common Foundry 1.0.16 wallet shows checksummed `cmfd1…` addresses. FreeForgeMiner now accepts them everywhere — HiveOS wallet template, Windows `start.bat` (`WALLET`), `--miner` — next to the old 64-hex form. The checksum is verified: a mistyped or truncated address is refused with a clear message (`address checksum does not match…`, `address is for another network…`) instead of mining to a wrong key. Both forms decode to the same 32-byte key, which is what the pool receives, so **`cmfd1…` and hex pay the same account** (verified on Aria: a `cmfd1…` worker is credited to the same payout as the hex workers). The miner prints both forms at start: `Payout: cmfd1… (hex …)`. Address codec taken unchanged from upstream 1.0.16 (MIT).
- **No more `duplicate_share` after a restart.** The pool's nonce origin depends only on the job and the session, so a miner restarted inside the same block searched the same nonces and found the same shares again. The search now starts at a random offset on every connect.
- **Regression test with the official 1.0.16 fixture** (`tests/upstream-1.0.16/`): our GPU worker reproduces the published reference output byte for byte (`fe67b80a…f4a7a7`) on RTX 30, RTX 40 and the Windows build, in both modes; GPU digests 32/32.
- Mining code, kernels and hashrate are the same as 1.2.3 — update if you use (or will use) a `cmfd1…` address or saw `duplicate_share` after restarts. The pool protocol did not change in Common Foundry 1.0.16, so 1.2.3 keeps working too.
